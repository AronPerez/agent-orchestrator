## What

A session and a project now carry the host they live on. Every read takes
a `Ref = {host, id}` and dispatches through `clientFor(ref.host)`, every
query key carries `refKey(ref)` instead of a bare id, and routes become
`/host/$hostId/session/$sessionId` and
`/host/$hostId/project/$projectId`. The four paths those replace are kept
as redirects to the local host.

**Everything here is mechanical except the redirect layer**, which is new
code and is the reason your existing deep links keep working.

## Why

Part of the remote-hosts series proposed in #RFC. This is the slice that makes the rest of the app able to say *which machine* a session belongs to, and it lands dark: with the Remote hosts flag off, `connectedHosts()` is `[]`, every `Ref` carries `LOCAL_HOST`, and `clientFor(LOCAL_HOST)` is the client `apiClient` already was. Read any hunk in this PR and it is an identity transformation.

Ids are never rewritten. A project id is `filepath.Base(path)` on every machine, so two machines that both cloned this repository both call the project `agent-orchestrator` and both number their sessions from one. `Ref` qualifies ids at the addressing boundary and nowhere else, which keeps parity with each daemon's own CLI and URLs.

## How

The transformation is one rule applied consistently:

```ts
// before                                    // after
apiClient.GET(path, {                        clientFor(ref.host).GET(path, {
  params: { path: { sessionId } } })           params: { path: { sessionId: ref.id } } })
function f(sessionId: string)                function f(session: Ref)
["session-usage", sessionId]                 ["session-usage", refKey(session)]
workspaces.find(w => w.id === id)            workspaces.find(w => w.host === r.host && w.id === r.id)
```

Making `host` a required field on `WorkspaceSession` and `WorkspaceSummary` is what makes the compiler enumerate the work: `tsc --noEmit` reaches zero with no `as any`, no `as unknown as`, no `@ts-ignore` and no non-null assertion added anywhere. The compiler is not a complete oracle here, though — a hook whose signature is `(sessionId: string)` still accepts `session.id`, so the read threading was driven by the call sites rather than by the error list.

**Mutations are deliberately left alone.** `POST`/`PATCH`/`DELETE` still go through `apiClient` at the end of this PR and are converted in follow-ups, split by area. That seam is what keeps this PR readable.

`routeTree.gen.ts` is tracked and generated; it is regenerated by `@tanstack/router-generator`, not hand-edited.

## Testing

`cd frontend && npm run typecheck && npm run typecheck:e2e && npx vitest run src/renderer` — 140 files, 2025 tests. On the base branch the same command is 139 / 2019; the difference is one new file, `routes/-session-route.test.ts`, with two host-qualified route cases and four redirect cases.

Upstream's existing suites are the regression check: this is an identity transformation with one host, so a test whose *behaviour* changed would be a bug in the conversion. The tests that did change assert a query key or a URL, both of which legitimately move.

No Go or OpenAPI surface is touched, so the `go` and `api-drift` CI jobs are unaffected.
